### 4. Technical Explanation Prefix Protection Protocol

In Domain 1, hardcoding option letter prefixes in explanations caused severe defects when answer keys were permuted (e.g. an explanation stating *"Option A is correct"* while the key was Option D).

In Phase 7, this vulnerability was eliminated through the following architectural measures:
1. **Dual-Layer Architecture:** The semantic rationale is stored in structured form within \x60explanation_detail.correct\x60 and \x60explanation_detail.incorrect\x60 without relying on hardcoded option letters.
2. **Dynamic Generation:** When options are permuted, the flat explanation strings (\x60explanation\x60 and \x60explanation_th\x60) are programmatically generated using the active \x60correct_idx\x60.
3. **Automated Verification:** 100% of the questions in \x60domain-2-revalidated-candidate-bank.json\x60 have been asserted via unit test to guarantee that \x60explanation_th.startsWith("ข้อ " + letters[correct_idx])\x60 and \x60explanation.startsWith("Option " + letters[correct_idx])\x60.

**Result:** Zero answer-explanation contradictions across all 26 candidate questions.
